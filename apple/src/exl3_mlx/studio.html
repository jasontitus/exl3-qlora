Data and resource settings

Keep examples from the same source or commit family together to avoid train/test leakage.

Zero-based block IDs 0–39. Blank selects all 40; 39 selects the last block. Each selected block adapts wq_a and wo_b. Full-model context is preserved. This setting is fixed when you check data; selecting fewer blocks is not a proven quality fix.

BF16 bypasses differentiable-path activation roundtrips while keeping packed weights, FrozenIndexer quantizers, BF16 casts and normal routing. It changes the zero-adapter result, needs its own baseline and is not a verified quality fix. Resume keeps the saved mode.

Larger chunks change floating-point rounding and require a new project. Benchmark before choosing 8192; resource profiles keep the default 512.

Development reserves 32 GiB for the system and keeps up to 8 GiB packed weights with decoded caching off inside the 80 GiB process limit. Requires 112 GiB reclaimable at startup. Decoded caching is experimental and slowed the measured MoE-layer workload.

Off by default. Reuses complete context before the earliest adapted block on repeated examples; no reuse when block 0 is adapted. Fits inside the process limit.

2. Train a pilot

Start with two updates to check the workflow. More updates are needed to assess learning; validation chooses the best saved adapter.

Stopping safely can take several minutes. Completed checkpoints support exact optimizer resume.

3. Compare and try

Uses held-out test data, or labels validation-only results as development. Loss improvement alone does not establish task quality.
