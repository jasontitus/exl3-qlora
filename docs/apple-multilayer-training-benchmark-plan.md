# Prospective last-one, last-two, and last-four attention-adapter comparison

This is a source-grounded benchmark proposal, not an executable campaign or a claim that additional layers fit, train correctly, run faster, or improve quality. The active 458-update run, its settings, runtime-v5, 229/0/16 split, heldout references, and caches remain unchanged. No MLX import, model payload read, GPU test, or training was performed to prepare this plan. `plan.json` and `source-check.json` bind the exact evidence and CPU arithmetic.

The likely cost driver is the longer differentiable suffix, not adapter storage. Runtime-v5 already accepts multiple attention-adapter layers, but its existing synthetic composition tests do not qualify the actual last-two or last-four model suffix. Start with these correctness and resource gates; measure cost before committing to the proposed longer comparison.

## What the inspected source establishes

`deepseek.py` wraps the two projections at each selected layer and sets the cache boundary to the earliest selected attention/expert layer, even when B is zero. It enables both block and nested attention recomputation when block checkpointing is enabled. Only the earliest trainable block may discard its frozen incoming-state VJP; later blocks must propagate gradients through hidden/hyperconnection state and frozen native/MoE computations. The cache includes hidden, hyperconnection and shared attention state; a block39 cache cannot be used before38 or36.

The actual configuration has no new compressed-KV producer or Engram in36–39: these layers reuse source20 KV. Layer36 is an index source. Its forward sparse choices are recomputed from current activations; routing IDs have no derivative in the declared surrogate. Last-four therefore needs a live routing check, including contexts beyond512 and window128 boundaries. A fixed-route, anchored quantizer/STE oracle is useful for the implemented first-order derivative; ordinary finite differences across quantization or selection discontinuities are not an exact oracle.

`native.py` computes the frozen quantized base path while inherited MLX-LM LoRA uses the original activation for its residual. Existing tests cover two synthetic TrainingBlocks, shared KV, FP32/BF16, zero/nonzero B, nested recomputation, Adam updates, and an independent anchored NumPy64 oracle. Prefix-cache fixtures use small custom blocks; selection/export tests use fake children. These are useful mechanisms and regression starting points, not full-model layer38/36 qualification. The pinned source comparison records where current product and runtime differ; do not substitute current product wholesale for runtime-v5.

## Matched inputs and initialization

Use fresh sibling arms, never warm-start last2/last4 from the current trained last1. The current run remains a historical reference, not a matched timing replicate. Copy the exact frozen prepared/raw data and provenance bindings; retain complete IDs, masks, EOS, sampler seed8, batch1, accumulation1, learning rate5e-5, clip1, Adam defaults, chunk2048, checkpoint activation arithmetic, block/nested recomputation and TF32-off. No truncation, repacking, selection, heldout replacement, or per-arm tuning. Each step is one item's mean target loss; diagnostic target-token share alone is not its update weight.

An isolated future initializer must publish one nested four-layer factor bank before training, using the runtime's initialization distribution and a preregistered deterministic RNG protocol. Load exact subsets for each arm: shared layers' A bytes must match; all initial B bytes must be positive F32 zero. Bind the initial RNG state and reset it identically after initialization. Same global seed alone is insufficient because additional earlier adapters consume draws. This initializer is a required reviewed addition, not an existing qualified CLI feature. For every endpoint derive an arm-specific matched control from that endpoint's exact A/header/config, zeroing only B. Do not equate an absent/rank-zero adapter graph with a rank4 zero-B graph. Test initial cross-arm forward agreement; if casting/graph differences remain, report them and use within-arm zero-B deltas without claiming identical starting predictions.

## Gates before timing or sustained training

1. **Complete derivative composition.** Extend the existing fixtures to one/two/four suffix blocks, all4/8/16 factor arrays and incoming hidden/hyperconnection/shared-KV states. Compare direct, block-recomputed and nested-recomputed loss, gradients and two Adam updates against the declared anchored oracle, with predeclared tolerances. At initial B=0, A gradients are expected to be zero; check finite nonzero B participation in each eligible block and A participation after a nonzero-B/subsequent-step case. Do not require every element to be nonzero. Include real native quantized and streamed EXL3 paths in an independently reviewed actual-shape qualification, with eager reference or a separately justified reference if memory prevents it; a skipped reference is an unresolved gate.
2. **Boundary and routing correctness.** For boundaries39/38/36 compare uncached, cold-insert, RAM-hit, disk-hit/fresh-process and post-suffix-update paths, including loss/all gradients/optimizer state. Validate complete cached KV/index state, training/eval mode separation, read-only frozen bytes and missing/corrupt/foreign-boundary rejection. For last4 record layer36 IDs and verify forward reselection under changed activations, without inventing gradients for discrete IDs. Never share prefix directories between arms. Suffix updates may reuse only the matching frozen prefix.
3. **Optimizer and reload.** Assert exact selected names, shapes, dtypes and finite values; base tensors stay frozen. Compare uninterrupted versus save/reload/next-update adapter bytes, Adam moments, RNG, sampler cursor and metrics for each scope. Include sparse optimizer trees, wrong-layer/config rejection before mutation, partial/corrupt checkpoints and duplicate producers. Existing last1 checkpoint receipts are insufficient.
4. **Resource and lifecycle.** Use one exact execution host/device, storage path, implementation, environment, common cache quotas and process/reserve policy. The bound current M5 reference is80GiB process/8GiB reserve, packed6144MiB, decoded0, prefix RAM1024MiB, disk64GiB, allocator256MiB; this is an unmeasured candidate for additional layers, not permission to apply an8GiB reserve on Studio. Any future Studio plan retains its32GiB reserve and requires a separately sealed common process budget for all arms. Independently preflight the longest complete train row/update and test forward in disposable models, then a fixed train-only short/median/long sequence, cold and repeated. Record process/MLX/allocator/cache peaks, pressure/swap growth, disk quota, I/O, leases and terminal child ownership. A failed arm is infeasible under that profile; do not silently increase its budget, truncate a row, change precision/recomputation or reduce the reserve. A resource amendment must be common and separately preregistered before all-arm comparison.

More trainable layers require input VJPs through more frozen expert blocks. A6GiB packed quota may retain one layer's approximately4.762GiB bank but cannot be assumed to retain multiple layers or avoid churn. That bank figure is historical layer39 metadata, not a measured traffic forecast or a verified sum for36–38. Recompute exact per-layer inventory and frozen-state shapes. The bound last1 estimate is51.373GiB for229 train+16 test unique prefix entries, not an estimate already validated for the other boundaries. Keep each arm's disk quota equal and charge any eviction/refill cost.

## Two distinct comparisons, fixed before scores

**Equal exposure:** primary future endpoint458 updates, exactly two visits to each of229 train rows in runtime seed8 order; no best-checkpoint selection. All arms see the same854,144 supervised-token occurrences and identical ordered serialized inputs/masks. Report229 as a predeclared secondary endpoint only if separately retained before execution. Preserve final458 full16 evaluation of the current campaign regardless of this proposal.

**Equal wall time:** a separate estimand, proposed cutoff14,400 seconds from that arm's process creation, including full identity hashing, model initialization and cache fill. Use the latest fully committed checkpoint published no later than the cutoff; if none exists, report zero completed updates. Do not include a checkpoint that finishes afterward or extend the budget for a slow arm. A reviewed retention hook must preserve that checkpoint despite keep2 rotation, recording the final eligible checkpoint plus the next completion/budget observation. The full equal-exposure trajectory may continue afterward; its later results must not leak into the timed endpoint. Record unequal update counts, target/serialized tokens and exact source-family exposure. No automatic quality-driven checkpoint choice. The14,400-second candidate and458-step cost require separate execution approval; this artifact launches neither.

Primary feasibility/cost pass is one seed8 replicate, in preregistered order last4,last1,last2, with explicit single-replicate limitations. A robust benefit claim needs a separately budgeted matched-seed extension, with cyclic arm order and identical within-seed initial factors/data; no standard error or significance claim from one run. The existing active last1 run cannot stand in for a fresh matched arm.

For **cold** report fresh-process/fresh-owned-cache wall time and first update, including mandatory hash scans. This does not mean cold OS pages: do not purge OS caches or stop unrelated processes. For **warm** report an observed same-arm cache hit on the same complete row, separately from the complete first/second-epoch throughput; never prewarm one arm for free. Capture monotonic process/phase/update/checkpoint times, fullhash duration, logical streaming loads/evictions, prefix reads/writes and OS I/O separately. Runtime training elapsed time excludes construction; launcher wall time is the cost denominator. Report all measurements/failures, medians/ranges only across actual repetitions, and ratio uncertainty honestly. Do not extrapolate2x/4x cost from layer count or factor bytes.

## Quality reporting and decision

Evaluate every admitted endpoint and its matched zero-B control on all16 unchanged heldout rows, same host/arithmetic and complete teacher-forced targets. Use immutable report snapshots plus the existing token/category auditor. Report token-weighted NLL, exact top1 counts, corrected/regressed tokens, per-item and source-stratum deltas, and explicit zero-count categories. Separate added executable Metal/host code from removed/context code, comments, headers/tool syntax, rationale and EOS. The frozen16 have only5 rationale tokens and16 EOS tokens; they cannot support broad reasoning or functional-code claims. Source-disputed reference targets remain fixed and disclosed; matching them is not proof of correctness.

Generated-patch evaluation is a separate capability gate. The reviewed native serving loader currently accepts only layer39's four factors; last2/last4 are not supported merely because the trainer accepts their scope. First extend and independently qualify every projection/cache/prefill/decode path, exact keys/config/bypass coverage, zero-B and nonzero numerical controls. Bind the same base and serving arithmetic for all arms; serving transfer is not trainer-forward parity. Then use the already fixed prompt/decoding/rationale rubric and generated-candidate replay/source-ABI/compile/all224 numeric gates before any12-workload paired timing. Preserve malformed/failed outputs. One full-kernel task is a narrow case study, not general code or reasoning quality. No new task mining or heldout-guided setting search is part of this plan.

Publish a cost/benefit table with observed fit status, end-to-end wall time, update/target-token throughput, memory/disk peaks, heldout added-code delta and generated-candidate outcome for each arm. Until the above gates and matched measurements pass, the defensible answer is that additional layers offer more adaptation capacity at an unknown extra compute/I/O cost and unknown quality benefit. A source-only plan cannot choose a winning layer count.
